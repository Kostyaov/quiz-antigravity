# Оновлення сайту після доопрацювання

Це головний робочий процес для звичайних змін: поправити сайт локально, перевірити, а потім оновити production.

## 1. Почати локально

```bash
cd /Volumes/ExtraStorage/2026/04_Programming/01_Active/quiz-antigravity
npm run dev
```

Відкрий:

```text
http://localhost:5173/
http://localhost:5173/admin
```

Локальна адмінка:

```text
admin@local.test / admin123
```

## 2. Внести зміни

Зміни можуть бути:

- у коді React/CSS;
- у логіці тестів;
- у документації;
- у локальній конфігурації через адмінку;
- у Firebase rules.

Важливо: локальна адмінка не змінює production Firebase.

## 3. Перевірити локально

Перед деплоєм варто вручну перевірити:

- головна сторінка відкривається;
- вибір навчального циклу працює;
- mobile menu не ламається;
- `/admin` відкривається;
- зміни зберігаються локально;
- тести відкриваються;
- статистика/CSV працюють, якщо зміни стосувалися статистики.

## 4. Запустити автоматичні перевірки

```bash
npm run lint
npm run build
npm run security:check
```

Якщо щось падає — не деплоїти, спочатку виправити.

## 5. Зробити dry-run

```bash
npm run deploy:vps:dry-run
```

Це корисна репетиція:

- перевіряє SSH;
- збирає production build;
- запускає security check;
- показує, які файли `dist/` були б змінені.

## 6. Завантажити на сайт

```bash
npm run deploy:vps
```

Скрипт створить бекап старого `dist/`, завантажить новий і перевірить сайт.

## 7. Перевірити production

Після деплою відкрий:

```text
https://uames.pp.ua/
https://uames.pp.ua/admin
```

Перевір:

1. Головна сторінка відкривається.
2. Випадаючий список подій виглядає нормально.
3. Розділи `Програма`, `Фото`, `Лекції`, `Презентації`, `Тести` працюють.
4. Production-адмінка приймає Firebase email/password.
5. Якщо змінювалася статистика — CSV відкривається в Excel.

Якщо браузер показує стару версію:

- `Cmd + Shift + R` на macOS;
- `Ctrl + F5` на Windows;
- або приватне вікно.

## Якщо змінювався тільки контент в адмінці

Якщо ти просто додав новий цикл, посилання, тест або програму через production-адмінку — VPS deploy не потрібен. Дані вже збережені у Firebase.

VPS deploy потрібен, коли змінювався код або статичні файли проєкту.

## Якщо змінювався `database.rules.json`

Це окремий процес:

1. Зробити backup Realtime Database у Firebase Console.
2. Перевірити правила локально через:

```bash
npm run build
npm run security:check
```

3. Задеплоїти rules:

```bash
firebase deploy --only database
```

4. Перевірити `/admin`, збереження конфігурації і проходження тесту.

## Якщо після деплою щось зламалося

1. Не панікувати — скрипт створив бекап.
2. Подивитися rollback-команду в кінці виводу `npm run deploy:vps`.
3. Якщо вивід втрачено, подивитися список бекапів:

```bash
ssh root@198.46.175.223 "ls -lh /root/quiz-app-backups"
```

4. Виконати rollback, як описано в [Бекап, rollback і troubleshooting](./09-backup-rollback-troubleshooting.md).
